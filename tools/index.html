Onboard a client

The five-step workflow, in order.

1 · The config template Private

Copy to embed/clients/<slug>.js and fill in every ASK THEM. About 20 minutes once you have their answers. Never put a key or password in here — it is served to browsers.

2 · Preview and try to break it Private

Ask it things badly and misspelled, the way a distracted person on a phone types. This is where you find the keyword gaps.

3 · Send them the install page Private

One line to paste, with step-by-step for Squarespace, Wix, WordPress, Shopify, GoDaddy/Weebly/Square and raw HTML. Plus a verification checklist.

What the client pastes
<script src="https://YOUR-DOMAIN/embed/chat.js" data-client="<slug>" defer></script>
When their prices change, you edit their config file here and redeploy. Their website is never touched again. That is the retainer, and it is why they can't take the code and leave.

About the missed-call app: the original is a Node server with a SQLite database. The copy here is a static port — same templates, same segment maths, same log — with the back end replaced by /missed-call/api-shim.js, which keeps everything in your browser's local storage. Nothing was lost in the move, because the server was already simulating the text. It cannot send a real one, by construction. Change a template rule in the server and you have to change it in the shim too, or the demo stops matching the product.
